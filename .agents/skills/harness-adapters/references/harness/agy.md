# Antigravity CLI (`agy`)

Verified 2026-09-18 on `agy` 1.2.6 for macOS arm64 crewmate and scout work through tmux only.
It is not a primary or secondmate runtime because it has no verified Firstmate turn-end hook or primary supervision protocol.
`bin/fm-spawn.sh` must refuse it outside this scope rather than presenting an unsupervised worker as dispatchable.

## Operating facts

| Fact | Value |
| --- | --- |
| Binary and identity | `agy`; its live interactive process and tmux foreground `comm` are exactly `agy`, so `bin/fm-harness.sh` and `bin/backends/tmux.sh` match only that exact name. `bin/fm-spawn.sh` refuses the spawn outright when that name is absent from PATH, naming the installer, because quota selection can hand back agy on unmeasured quota and an uninstalled host is exactly what reports that. |
| Environment marker | agy sets `ANTIGRAVITY_AGENT=1` on its tool subprocesses, with `ANTIGRAVITY_AGENTAPI_EXE` pointing at the running binary plus conversation and trajectory ids (verified live, agy 1.2.6). It sets no `GEMINI_CLI`, so the gemini marker never claims it, but it does NOT scrub an inherited `CLAUDECODE`: before `bin/fm-harness.sh` tested `ANTIGRAVITY_AGENT` first, a live probe inside an agy tool subprocess under a claude primary answered `claude`. The marker arm is ordered ahead of the `CLAUDECODE` arm for exactly the reason cursor, gemini, and rovo are, and `bin/fm-spawn.sh` clears an inherited `ANTIGRAVITY_AGENT` at the shared launch boundary so the new precedence cannot misread another harness's worker. agy's own launch clears every marker ranked above it - the cursor pair through the shared prefix, `ATLASSIAN_AGENT_TYPE` and `ROVODEV_CLI` in its template - so an inherited runtime marker cannot make an agy worker report another harness. |
| Launch | `agy --dangerously-skip-permissions --model <model> --effort <low\|medium\|high> --prompt-interactive=<brief>`; `--prompt-interactive`, not `--print`, starts the supervised interactive turn. |
| Permission posture | `--dangerously-skip-permissions` is a per-launch worker flag approved for this fleet task, never a persistent Antigravity setting. The adapter does not pass `--sandbox`, and it must never set a persistent `proceed-in-sandbox` policy. |
| Trust and delivery | A new worktree stops at `Do you trust the contents of this project?` with `Yes, I trust this folder`; `agy_wait_for_delivery` sends one Enter only when both strings are visible. Delivery is then confirmed on the busy footer OR on the submitted brief echoed above the composer, because the footer is transient and a fast turn can settle inside one poll gap. The echo marker is taken from the brief's TAIL: a long brief scrolls its own head out of the pane while the tail stays adjacent to the response (measured live). That tail is fleet-constant boilerplate, and neither screen signal proves the current launch when the same text is already on the pane, so both are read only below this launch's boundary: the `export FM_TASK_ID=<id>` row, the task's own export typed on its own line ahead of the launch command, taking its last occurrence (an optional `export TRACEPARENT=<carrier>` row can sit between it and the launch, and carries no agy signal), and read from a joined (`-J`) capture so a boundary tmux split across rows is still matchable. A capture carrying no boundary withholds every signal while none has been seen yet; once one has, a later capture without it is agy's own screen and is read whole. Once agy's alternate-screen TUI takes over, tmux captures only that screen and no earlier scrollback reaches the gate (measured), which is what makes that later fallback safe. If the boundary is never observed at all, `fm-spawn.sh` retires the endpoint and says the boundary was not observed rather than claiming the brief was refused, because it never established what this launch printed. Both checks stay live for every poll, so a reused endpoint's answered prompt neither draws a stray Enter into a live turn nor hides a dialog this launch genuinely raised. |
| Busy and turn end | The current bottom footer is `esc to cancel` during a running turn and is absent once the turn settles or is interrupted. `fm_busy_agy_tail_busy` checks only the last twelve nonblank rows, so the affirmative and absent directions classify `busy agy-regex` and `idle agy-regex`. |
| Steering | The idle TUI composer is a `>` row between two full-width `─` divider rows. That shape is not container proof on its own, so `bin/fm-tmux-lib.sh` applies `fm_composer_classify_agy_divider_pair` only for a pane whose foreground process is `agy` (`fm_tmux_pane_is_agy`): an idle agy composer returns `empty` and typed text returns `pending`, while the identical rows under any other process, including a dead shell showing agy's leftover screen, stay `unknown`. |
| Interrupt and exit | One Escape interrupts a running turn and leaves the process interactive; `/quit` exits it. |
| Resume | `--conversation <conversation-id>` restored the same conversation and recalled its token; `--continue` selected that most recent conversation and recalled the same token (verified in print mode on 1.2.6). Deterministic worker recovery still uses relaunch from the brief because Firstmate has no resume verb. |
| Quota family | agy has its own `quota-axi` provider row, named `agy` (`quota-axi --provider agy`, plan `Google AI Pro`), and that one row measures both its Gemini and its Claude/GPT windows. `bin/fm-quota-choose.sh` maps the harness to that family from agy's own authenticated account rather than from the candidate model name, so a `claude-*` model dispatched through agy is checked against agy's row and never against the separate Claude subscription. Antigravity not running is the ordinary state before a worker is launched, and the row then reports stale and unresolved-window attention only, so an agy candidate whose quota cannot be measured stays eligible and `fm-quota-choose.sh` discloses the missing measurement on stderr instead of presenting it on stdout as headroom. An `exhausted_now` runway or a known zero still vetoes agy. |
| Model and effort | `agy models` is account-specific and includes Gemini, Claude, and GPT-OSS entries on the verified account. `--model` and `--effort` are separate flags; effort accepts only `low`, `medium`, or `high`, while `xhigh` and `max` stay in task metadata and are omitted at launch. |

## Trust persistence

Accepting the prompt persisted workspace trust in `~/.gemini/antigravity-cli/settings.json` under `trustedWorkspaces`.
The resulting file contained `/Users/davidsair` and `/Users/davidsair/.treehouse/firstmate-8bf1b0/5/firstmate`.
This post-accept snapshot does not establish which entry was newly written or whether every worktree appends an entry, so do not treat it as blanket-trust evidence.
No `enableTerminalSandbox` or `toolPermission=proceed-in-sandbox` field was written during the verification.
Treat each new worktree as potentially requiring its own prompt and record a newly observed settings shape before broadening this behavior.

## Linux

Antigravity's [official installation page](https://antigravity.google/docs/cli/install/) publishes a Linux installer: `curl -fsSL https://antigravity.google/cli/install.sh | bash`.
On the DGX, run it in an attended terminal, complete its interactive sign-in, and then re-run the live tmux verification before adding `agy` to a Linux home's dispatch configuration.
The installer answer removes the platform-availability blocker for the three DGX workers, but no DGX installation or verification is claimed by this adapter record.
